# 포트폴리오 인터뷰

> 작업 규칙은 **`AGENTS.md`** 에 있습니다. Claude 와 GPT 는 폴더를 열 때 그 파일을 자동으로 읽습니다.
> 기록은 이 `README.md` 한 곳에만 남기고, 지나간 것은 딱지를 붙이지 말고 지웁니다.

이력서를 못 쓰겠는 사람이 **질문에 답하기만 하면** 포트폴리오 한 장이 나오는 웹페이지.
파일 하나(`index.html`)가 전부다. 서버도, 빌드도, 라이브러리도 없다.

## 왜 이렇게 만들었나

빈 이력서 양식 앞에서 멈추는 이유는 쓸 게 없어서가 아니라 **무엇을 쓰라는 건지 모르기 때문**이다.
그래서 양식을 주는 대신 질문을 준다. 질문은 세 가지 규칙으로 썼다.

1. **직함이 아니라 한 일을 묻는다.** "무슨 일이었나요? 직함 말고, 실제로 무엇을 했는지."
2. **잘한 것만 묻지 않는다.** "처음에 제일 안 풀렸던 게 뭐예요", "다시 한다면 뭘 다르게"
   — 막힌 지점을 말할 수 있는 사람이 일을 해 본 사람이다.
3. **모든 질문에 `예)` 를 붙인다.** 답의 수준을 글로 설명하는 것보다 예시 한 줄이 빠르다.

경력이 화려한 사람을 위한 도구가 아니다. 동아리·알바·봉사·혼자 만든 것을
같은 무게로 묻고, "숫자가 없으면 전에는 ~였는데 지금은 ~다 로 쓰면 된다"고 안내한다.

## 내보내는 방법

브라우저 안에서 시작한 파일 내려받기는 막히는 환경이 많아 **전부 복사 방식**으로 뺀다.

- **인쇄 · PDF로 저장** — `window.print()`. 인쇄 CSS가 조작 버튼을 다 숨긴다.
- **글로 복사하기** — 기존 이력서 양식이나 메일에 붙여 넣을 순수 텍스트.
- **웹페이지 파일로 복사하기** — 완성된 독립 HTML 문서. 메모장에 붙여 넣고
  `portfolio.html` 로 저장하면 그대로 열린다. 깃허브 페이지에 올려 주소를 만들어도 된다.
- **답 백업 / 불러오기** — 답 전체를 JSON 한 덩어리로 주고받는다. 기기를 옮길 때 쓴다.

## 답은 어디 저장되나

**`localStorage` 뿐이다.** 서버로 가지 않고, 링크를 받은 다른 사람에게도 보이지 않는다.
개인 이력을 다루는 도구라 공유 저장소를 일부러 쓰지 않았다 — 링크 하나로 남의 이력이
열리면 안 되기 때문이다. 대신 창을 지우거나 기기를 옮기면 사라지므로,
마지막 화면의 **답 백업하기**를 안내 문구로 두 곳에 넣어 뒀다.

## 예시 인물

시작 화면의 **예시로 채워 보기**를 누르면 가상 인물 "김하람"의 답으로 전부 채워진다.
완성본이 어떤 모습인지 먼저 보라고 넣었다. 이름에 `(예시 인물)`을 박아 두어
실제 사람의 이력으로 오해될 여지를 없앴다.
